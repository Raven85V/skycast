# Участие в проекте

Спасибо, что хотите помочь SKYCAST! Ниже — как собрать проект и что нужно для PR.

## Как сообщить о проблеме

1. Проверьте, нет ли уже похожего issue.
2. Создайте issue по шаблону **Bug report** и укажите:
   - плату и версию прошивки (видна в веб-интерфейсе и в логе при старте);
   - что делали, что ожидали, что получилось;
   - лог с UART (115200) — особенно строки `Погода:`, `История:`, `OWM:`;
   - скриншот экрана, если проблема визуальная.

## Как предложить функцию

Создайте issue по шаблону **Feature request**: опишите задачу, а не решение.
Например, «хочу видеть УФ-индекс на втором экране», а не «добавьте поле uv в парсер».

## Сборка

Проект использует **pioarduino** (Arduino core 3.3.7) — обычный PlatformIO с
`espressif32` из реестра **не соберётся**.

```bash
# зависимости подтянутся при первой сборке
pio run -e skycast            # прошивка
pio run -e skycast -t upload  # прошить
pio run -e skycast -t buildfs # собрать LittleFS-образ
pio run -e skycast -t uploadfs
```

Требования: Python 3.10+, PlatformIO Core, ~2 ГБ свободного места
(пакеты Arduino core 3.x большие).

**Важно**: путь к проекту не должен содержать кириллицу — иначе падает линковка
(xtensa-ld не умеет в не-ASCII пути к map-файлу).

## Структура кода

| Путь | Что там |
|---|---|
| `src/main.cpp` | цикл, режимы экранов, обработка касаний, OTA |
| `src/ui*.cpp` | отрисовка экранов (главный, второй, «Дома», часы, почасовой) |
| `src/weather.cpp` | источники погоды, парсеры, история давления |
| `src/settings.cpp` | настройки в NVS, санитайзер значений |
| `src/web_ui.cpp` | веб-интерфейс и HTTP API |
| `src/integrations.cpp` | MQTT, Telegram, очередь команд |
| `custom_components/skycast/` | интеграция Home Assistant (Python) |
| `skycast-sensor/` | прошивка беспроводного датчика |

## Правила PR

1. Одна логическая правка = один PR. Не смешивайте рефакторинг и новую функцию.
2. **Собирайте перед отправкой**: `pio run -e skycast` должен завершиться успешно.
3. Соблюдайте существующий стиль: 2 пробела, `snprintf` вместо `String` в отрисовке,
   комментарии по-русски.
4. Не добавляйте в репозиторий: `secrets.h`, логи сборки, `firmware.bin`, `littlefs.bin`,
   картинки больше 300 КБ.
5. Для изменений в интеграции HA — проверьте синтаксис Python (`ast.parse` достаточно)
   и обновите `manifest.json` (версия) и `CHANGELOG.md`.
6. В описании PR укажите, что проверено на железе, а что нет.

## Версии и релизы

- `manifest.json` — версия интеграции, `vX.Y.Z` — тег релиза.
- Перед релизом обновите `CHANGELOG.md`.
- Релиз собирается вручную: `pio run -e skycast` → приложить `firmware.bin` к релизу.
